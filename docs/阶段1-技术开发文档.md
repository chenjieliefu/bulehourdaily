# 第 1 阶段技术开发文档｜项目骨架 + 信息源与采集

> 配套文档：《微蓝日报 PRD》、《AI 产品 Vibe Coding 通用技术栈手册》、《技术适配声明》。
> 本文档只覆盖第 1 阶段。开发时不得提前实现其他阶段的能力。

## 一、阶段目标

对齐 PRD「一周 MVP 交付计划」的 **Day 1 + Day 2**，以及功能需求 **FR-01、FR-02** 和 FR-03 中的「确定性去重」部分。

- **交付范围**：
  1. 后端项目骨架（FastAPI 可启动、可测试）。
  2. 数据模型：信息源（Source）、来源条目（SourceItem）、采集运行记录（CollectionRun）。
  3. 固定信息源池：30–50 个种子信息源，可配置，只有运营者可改。
  4. 定时采集：每 30–60 分钟增量采集 + 手动触发入口。
  5. 来源条目存储 + URL 规范化 + 确定性去重。
  6. 最小验收界面：查看信息源列表、最近采集时间、来源条目列表、手动触发采集。
- **阶段产物**：一个能「启动 → 配置源 → 采集 → 看到去重后的条目」的本地后端。
- **验收标准（对齐 PRD）**：
  - 信息源包含唯一标识、类型、名称、URL、启用状态、可信级别（FR-01）。
  - 信息源变更只能由运营者执行（FR-01）。
  - 来源条目至少保存标题/正文、作者、原始 URL、发布时间、采集时间、信息源 ID（FR-02）。
  - 相同 URL 重复采集不创建重复条目（FR-02/FR-03）。
  - 页面显示「最近采集时间」（FR-02）。
  - 单一信息源故障不阻断其他来源采集（FR-02）。
  - 采集失败可追踪到具体信息源和失败时间（FR-02）。
- **明确不做**（后续阶段）：事件聚类、可信度标签、排序、日报生成、个性化、用户账户、邮件、正式前端。
- **本阶段打通的主链路片段**：`信息源配置 → 定时/手动采集 → 规范化去重 → 来源条目入库 → 最小界面可查看`。

## 二、技术适配摘要

- 引用《技术适配声明》结论。
- 本阶段采用：Python 3.11.9、FastAPI、Pydantic、pytest、Git。
- 本阶段启用：SQLite + SQLAlchemy + Alembic（多实体关系触发）；进程内调度器（暂不用消息队列）。
- 本阶段偏离/暂缓：X（推特）采集暂缓，用官方免费源（RSS/博客/GitHub）+ 模拟数据占位。
- 开发路径：**后端先行** + 最小验收界面（单个 HTML 挂 `static/`）。

## 三、技术栈与模型

- FastAPI + Uvicorn（Web/API）。
- SQLAlchemy 2.x + Alembic + SQLite（本地 `data/weilan.db`）。
- Pydantic v2（接口输入输出 + 校验）。
- httpx（采集 HTTP 请求）。
- feedparser（解析 RSS/Atom）。
- APScheduler（进程内定时任务）。
- pytest + pytest-asyncio（测试）。
- **模型：本阶段不调用任何大模型，无 Prompt。**

## 六、数据、资产与状态

### 数据表

**source（信息源）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK | 唯一标识 |
| name | str | 名称 |
| type | enum | `rss` / `github_releases` / `x`（x 本阶段为占位） |
| url | str | 采集地址 |
| enabled | bool | 启用状态 |
| credibility_level | enum | `official` / `media`（官方/媒体） |
| max_items_per_day | int | 单源每日进入日报的条目上限（FR-01 控源占比） |
| created_at / updated_at | datetime | 审计时间 |

**source_item（来源条目）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK | |
| source_id | FK | 所属信息源 |
| title | str | 标题或正文摘要 |
| body | text | 正文（可空） |
| author | str | 作者（可空） |
| url | str | 原始 URL |
| url_hash | str unique | 规范化后 URL 的哈希（确定性去重键） |
| published_at | datetime | 发布时间 |
| collected_at | datetime | 采集时间 |
| raw | json | 原始数据（用于追溯，不展示） |

**collection_run（采集运行记录）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK | |
| source_id | FK | |
| started_at / finished_at | datetime | |
| status | enum | `running` / `success` / `failed` |
| error_message | str | 失败原因（不记录凭据） |
| items_count | int | 本次采集到的条数 |

### 状态机（本阶段）

- 信息源：`enabled`（启用/停用），只有运营者接口可改。
- 采集运行：`running → success | failed`。失败可追踪到具体源和失败时间。

### 种子数据

- 提供 30–50 个种子信息源，放在可版本化的种子配置里（如 `backend/app/core/seed_sources.json`）。
- 构成：官方博客 RSS（OpenAI、Anthropic、Google DeepMind、Meta AI、Hugging Face、Mistral、xAI 等）+ GitHub Releases Atom（vllm、llama.cpp、transformers、ComfyUI、ollama 等）+ 一批 **X 账号（type=x，本阶段采集器返回空/模拟，标记「待接入」）**。
- 迁移时写入数据库，运营者可在界面上增删改。

## 七、API / 工具设计

统一前缀 `/api/v1`，统一错误结构 `{"error": {"code", "message"}}`。

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| GET | `/api/v1/sources` | 信息源列表（可按启用状态过滤） | 公开读（MVP） |
| POST | `/api/v1/sources` | 新增信息源 | 运营者 |
| PATCH | `/api/v1/sources/{id}` | 修改启用状态/上限/URL | 运营者 |
| DELETE | `/api/v1/sources/{id}` | 停用（软停用，不物理删除） | 运营者 |
| POST | `/api/v1/collect/run` | 手动触发一次全量采集（返回运行摘要） | 运营者 |
| GET | `/api/v1/source-items` | 来源条目列表（分页、按源过滤） | 公开读（MVP） |
| GET | `/api/v1/status` | 最近采集时间、各源成功/失败状态 | 公开读（MVP） |

- 采集为**后台任务**：手动触发立即执行，定时器每 45 分钟跑一次；单次运行记录持久化，进程重启后可查。
- 本阶段无 SSE（无流式生成需求）。

### 关键算法（确定性，非模型）

- **URL 规范化**：转小写 scheme/host；去掉默认端口；去 `utm_*`、`fbclid`、`gclid` 等追踪参数；去锚点；去尾部 `/`。
- **确定性去重**：规范化后 URL 取 SHA-256 → `url_hash` 唯一索引；重复采集命中即跳过（FR-02 验收）。

## 九、验收界面或纵向切片

- 类型：**临时验收工具**（非正式前端）。
- 形式：单个 `index.html` 挂在 `backend/app/static/`，原生 JS + fetch 调 `/api/v1`。
- 功能上限：① 信息源列表（含启用/类型/可信级别）；② 「立即采集」按钮；③ 来源条目列表（显示最近采集时间、去重后条数）；④ 采集失败源标红。
- 不含：登录、漂亮视觉、日报页面。

## 十、测试要求

### 第一层 mock 自动化测试（pytest，离线）

1. Source / SourceItem / CollectionRun 模型字段与枚举校验。
2. URL 规范化纯函数：追踪参数去除、大小写、尾部斜杠、锚点。
3. 确定性去重：同一 URL 两次入库只产生一条。
4. 采集器：用 mock 的 RSS 响应验证解析出标题/链接/时间；源不可达时记录 `failed` 且不影响其他源。
5. 枚举与状态流转：CollectionRun `running → success/failed`。
6. API：错误路径（源不存在、无效分页、无效请求体）返回统一错误结构。

### 第二层真实冒烟

- 本阶段无模型，**不需要真实模型冒烟**。
- 需做**真实采集集成测试**：对 2–3 个真实 RSS/GitHub 源实际跑一次，验证能拿到条目并入库（不依赖模型 Key）。

## 十一、验收清单（产品经理可照做）

- [ ] 我能启动项目（按 README 命令），浏览器打开一个页面能看到信息源列表。
- [ ] 页面上能看到 30–50 个信息源，有类型、启用状态、可信级别。
- [ ] 点「立即采集」后，页面上出现来源条目，并显示「最近采集时间」。
- [ ] 再点一次「立即采集」，条目数量不翻倍（说明去重生效）。
- [ ] 停掉/改坏一个源，其他源照常采集，失败源在页面上有提示。

## 十二、风险与待确认项

- **X 数据暂缓**：本阶段 X 账号只占位不真采，已记入决策备忘，商业上线前接入。
- **种子源质量**：30–50 个源的 RSS 有效性需实测，失效源会在验收界面标红，后续阶段统一清洗。
- **单源失衡控制**：本阶段只落 `max_items_per_day` 字段，实际限流在日报生成阶段（阶段二）生效。
- 必须由产品经理决定的问题：无。
