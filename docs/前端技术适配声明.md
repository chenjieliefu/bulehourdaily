# 前端技术适配声明

> 依据《AI Agent 产品 Vibe Coding 通用前端技术栈手册》第 23 节模板输出。
> 对应产品阶段：阶段 3（公开通用日报网站）。

## 1. 项目判断

- 产品类型：内容策展 + AI 生成的日报产品（Web）。
- 主要用户：抖音 AI 创作者（阅读日报的普通用户）；运营者质检界面为后续阶段。
- 主要终端：桌面 Web 优先，兼顾移动 Web（创作者常在手机上查看）。
- 新项目或已有项目：后端 FastAPI 已有（backend/）；前端从零新建 Next.js 工程。
- 本阶段业务目标：做出**公开通用日报网站**——无需登录即可阅读今日完整日报 + 按日期浏览最近 7 天 + 订阅价值说明。

## 2. 输入资料

- PRD：已读取。
- 后端手册：已读取。
- 接口文档：已有后端 `/api/v1`（reports、events、status 等，见 README）。
- 设计稿：**无**（待产品经理确认视觉方向）。
- 现有代码：有（backend/）。

## 3. 技术选择

- 框架与版本：Next.js（创建时锁定当前稳定版，预计 15/16）+ React 19 + TypeScript strict；本机 Node 24。
- 样式与组件：Tailwind CSS 4 + CSS 语义变量（颜色/圆角/间距统一）；自建轻量组件，本阶段交互简单，不引入 shadcn/ui 或组件库。
- 数据请求与状态：集中式 API 层（`lib/api`），页面不散落 fetch；本阶段以「读」为主，不引入 TanStack Query/Zustand。
- 流式通信：日报生成是后端「提交+轮询」任务，前端用**有节制的轮询** `/jobs/{id}`（公开页本身以读为主）。
- 表单方案：本阶段无表单（注册/画像在阶段 4）。
- 测试方案：ESLint + 类型检查（tsc）+ Vitest + React Testing Library + 生产构建作为交付门槛。
- 部署环境：开发期本地，前端 `:3000` 通过 `rewrites` 同源代理 `/api/*` 到后端 `:8000`；正式部署见《上线部署手册》（后续）。

## 4. Agent 状态

- 后端任务状态 `pending/running/success/failed` → 前端映射成统一状态展示（本阶段主要用于「生成日报/提取事件」按钮）。
- 等待确认/取消/断线恢复：本阶段公开页以「阅读」为主，无用户确认与取消交互；复杂恢复逻辑在阶段 4 个性化后按需补充。
- 任务 ID 与恢复入口：公开日报页不涉及（任务只在运营者触发生成时出现）。

## 5. 页面与产物

- 核心页面：
  1. 今日日报页（`/`）：日期、一句话摘要、3 个选题卡、热点速览、证据链接、事件时间、建议发布时机。
  2. 历史归档页（`/archive`、`/archive/[date]`）：按日期浏览最近 7 天通用日报。
  3. 订阅价值说明（日报页底部或独立区块）：说明通用日报 vs 个性化日报的差异。
- 核心业务闭环：打开首页 → 看到今日日报 → 点证据链接跳原文 → 切到前几天归档 → 正常阅读。
- 产物类型：纯文本日报（无图片/视频/音频）。
- 响应式目标：390px（手机）/ 768px（平板）/ 1280px（桌面）/ 1440px（宽屏）。

## 6. 偏离本手册的地方

- 无重大偏离。本产品形态是「日报」而非对话式 Agent 工作台，因此本阶段不引入流式输出、复杂任务中心与等待确认交互。
