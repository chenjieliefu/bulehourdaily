# 微蓝日报 V0.9 信息源重新选择

- 核查日期：2026-08-21
- 目标读者：中文 AI 内容创作者、自媒体创作者
- 本文范围：只选择信息源，不修改代码、线上配置或数据库，也不评估爬虫工具。
- 证据原则：只采用来源拥有者的官方博客、官方更新日志、官方 GitHub Releases/Atom 和项目当前代码；不把媒体转述当作事实来源。

## 一、结论

当前来源不是“太少”，而是**太宽、太杂且可用性被高估**：配置共有 43 个来源（41 个启用），包括 14 个 RSS、14 个 GitHub Releases 和 15 个 X 账号。线上现状中，15 个 X 来源只是占位，采集器明确返回空；部分 RSS 失败或返回 0 条；大量 Releases 的标题只是版本号，难以直接回答内容创作者最关心的“出了什么、能拿来做什么、是否值得做内容”。

建议 V0.9 首批压缩为 **10 个来源**：6 个可直接进入自动采集候选，4 个先作为官方页面观察源。先用小组合跑出一份有用日报，再扩源。

### 选择标准

一个来源进入首批，至少满足以下三项中的两项：

1. 能产生创作者可行动的信息：新模型、新创作能力、新工作流或平台能力变化；
2. 是发布方的一手内容，能直接作为日报证据；
3. 有稳定 RSS/Atom，或有结构清晰、更新时间明确的官方页面。

以下内容不作为首批主供给：综合科技热榜、公司综合新闻、只有版本号的高频依赖包更新、当前无法取得内容的 X 占位源。

## 五、上线前的最小验收

本次不改配置。真正更换来源时，建议只做以下一次小规模验收，再让用户确认：

1. 用 10 个首批来源试跑 24–48 小时；页面观察源允许暂时人工记录；
2. 新鲜度必须使用来源自己的 `published_at`，不能用刚入库的 `collected_at` 伪装成 48 小时内新闻；当前候选 66 条中有 45 条存在这种风险；
3. 每条日报候选必须能回链到发布方官网；
4. 纯版本号、无正文、发布时间不明的条目不进入 AI 摘要；
5. 每日目标不是“凑满数量”，而是 3–7 条真正能回答“发生了什么、为什么重要、创作者可以怎么用”的内容；
6. 试跑结果先由用户确认，再决定是否把页面观察源自动化或扩充第二批来源。

## 六、事实与推断边界

### 已核查事实

- 当前配置确有 43 个来源：14 RSS、14 GitHub Releases、15 X；41 个启用、2 个停用。
- 项目采集器对 X 类型直接返回空。
- 2026-08-21 直接检查时，OpenAI、DeepMind、Google AI、Hugging Face、NVIDIA、GitHub、Weaviate、HN 及各 GitHub Atom 可取得内容；Microsoft、xAI、Perplexity 返回 403；LangChain 与 LM Arena 当前地址落到 HTML 页面而非可解析 Feed。
- Stable Diffusion WebUI、MetaGPT、Microsoft AutoGen 的最新 Release 日期明显早于当前；不能承担“今日动态”供给。
- 线上采集结果还暴露了时间判断问题：一批旧内容因刚被采集而被当作 48 小时内候选。

### 产品判断

- “官方且可访问”不等于“适合日报”；对中文 AI 创作者，产品能力和创作工作流更新优先于基础设施版本与公司综合新闻。
- V0.9 应先以 10 个来源验证内容质量，不应立即修复和接入全部 43 个来源。
- 页面观察源能否自动化，应在看到真实内容产出后再决定；这一步不需要先采购爬虫工具。
