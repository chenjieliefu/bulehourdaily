## 一、结论先行

### 事实

1. V0.9 已经具备完整的页面和业务骨架：公开日报、归档、邀请注册、画像、个性化日报、创作方案、发布反馈、人工订阅、产品反馈和独立运营工作台均有实现；产品文档也将这些能力列为“已上线”。证据：`README.md:18-41`、`PRD.md:50-63`、`PRD.md:663-684`。
2. 前后端当前均在 veFaaS 正常发布并各有 1 个 Ready 的预留实例；2026-08-21 只读核查时，稳定 revision 分别为后端 6、前端 10。历史上线记录中的 revision 4/6 已不是当前版本。证据：veFaaS `app info`、`fn info`、`fn instances`、`app revisions` 只读查询；历史记录见 `docs/运营工作台-上线说明.md:77-94`。
3. 当前 V0.9 代码不是“可直接当作稳定线上版本”的状态：存在未鉴权写接口、草稿可能公开、生产数据持久性未在仓库内闭环、进程内调度/线程任务与 serverless 运行语义冲突、真实模型/真实送达尚未验收等上线风险。逐项证据见第五节。
4. 线上在 2026-08-21 又产生了新 revision，但 veFaaS revision 说明只记录 CLI 触发，不能据此证明它与 Git 标签 `V0.9` / 提交 `4c10129` 完全一致；仍需在下一次发布时建立提交到 revision 的明确映射。证据：veFaaS `app revisions` 只读查询；本地待发布说明见 `决策备忘.md:154-164`。

### 推断

- 如果“可运行姿态”指**可给少量受邀用户试用**，应先完成安全收口、公开内容边界、线上持久化/调度验证和 V0.9 重新发布；真实邮件和自动支付可以继续人工替代，但必须在界面和运营话术中明确。
- 如果“可运行姿态”指**可公开推广或收费**，还必须叠加真实信息供给、连续真实模型内容评测、送达、合规和漏斗采集；PRD 自己也把这些列为商业验证前未完成项。证据：`PRD.md:675-693`。

### 已锁定的首轮范围（用户于 2026-08-21 确认）

1. 首个线上目标是**受邀内测可运行**，不是公开收费。
2. 北京时间 08:00 的目标是**自动生成并自动公开**；当前只有 1 人运营，未来可再改为人工审核。
3. 首轮只要求网页可访问；**暂不做通知、支付或付款流程**。
4. 当前优先级只聚焦**公开日报与归档日报**，邀请用户的完整服务旅程排在其后。
5. 用户授权只读核查线上数据库、备份、实例和调度；未授权直接改配置、发布或批量实现。
6. 数据持久化路线最终确认采用首个过渡方案：**SQLite + 火山引擎 TOS 云端备份/启动恢复**。正式托管 PostgreSQL 仅对企业用户开放；MySQL 虽已配置到订单确认前，但用户因早期内测成本考虑决定暂不创建。

## 五、线上“可运行姿态”的阻塞项与风险

### P0：发布前必须处理

#### 1. 旧订阅写接口无鉴权

- **事实**：`POST /api/v1/subscriptions` 没有 `get_current_operator` 或其他登录依赖，调用方只要提供 `user_id` 就能创建订阅。`backend/app/api/subscriptions.py:31-37`。
- **对照事实**：新的运营订阅接口位于 `/admin/subscriptions`，整体受运营者依赖保护，并拒绝给运营账号开通。`backend/app/api/admin.py:39-40`、`backend/app/api/admin.py:97-107`。
- **推断**：公开部署时，旧接口可绕过运营权限和付款确认，应删除、停用或迁移为运营者鉴权接口后再发布。

#### 2. 外部采集／生成触发接口无鉴权

- **事实**：`POST /collect/run`、`POST /events/extract`、`POST /reports/generate` 均未声明用户或运营者依赖。`backend/app/api/collect.py:12-14`、`backend/app/api/events.py:15-18`、`backend/app/api/reports.py:24-27`。
- **推断**：任何访问者都可能触发外部请求、模型成本、后台线程和数据库写入，必须至少收口为运营者权限。

#### 3. 草稿可被公开列表和详情读取

- **事实**：公开日报列表返回所有 `DailyReport`，详情只按 id 查询，均未过滤 `status=published`。`backend/app/api/reports.py:30-32`、`backend/app/api/reports.py:60-64`。
- **事实**：前端首页直接读取列表第一份作为公开日报。`frontend/app/(main)/page.tsx:12-17`。
- **事实**：08:00 任务创建/覆盖的是 `draft` 日报。`backend/app/main.py:51-61`、`backend/app/services/report_generation.py:123-134`。
- **推断**：当天草稿可能在质检前直接成为公开首页第一份，违背“质检后发布”的产品约束。公开列表/详情必须只返回已发布内容，运营查询走 `/admin`。

#### 4. 线上数据持久化尚未在代码仓库形成闭环（2026-08-21 已进入发布验证）

- **事实**：默认数据库为本地 SQLite 文件，数据库层没有连接池、备份或恢复逻辑。`backend/app/core/config.py:5-10`、`backend/app/core/database.py:9-25`。
- **事实**：部署包排除本地 `data/` 与 `.env`。`backend/.vefaasignore:1-9`。
- **事实**：项目自己的部署手册说明 veFaaS `/tmp` 是临时存储，要求“预留实例 + 对象存储定期备份 + 启动恢复”；上线检查也要求实测重启恢复。`AI Agent 产品上线部署手册.md:407-417`、`AI Agent 产品上线部署手册.md:510-535`。
- **仓库搜索事实**：在 `backend/`、`frontend/` 内检索 `backup|restore|对象存储|tos|S3`，未发现业务数据库备份/启动恢复实现。
- **线上核查事实（2026-08-21）**：后端 `DATABASE_URL` 明确是位于 `/tmp` 的 SQLite；函数没有启用 NAS、TOS 挂载或 VPC，仓库也没有备份/启动恢复实现。当前只有 1 个 Ready 的预留实例，但该实例创建于当天后端 revision 6 发布时，说明发布/换实例会产生新的本地运行环境。
- **2026-08-21 后续进展**：已创建私有 TOS 备份桶、启用版本控制，并完成当前 V6 SQLite 数据库的一致性快照上传、下载回读、哈希比对与 SQLite 完整性校验；受保护账号只读指纹与线上一致。仓库已增加启动恢复、写请求后备份与周期备份实现，正在进行新 revision 发布和真实启动恢复验证。
- **结论**：首次正式备份已闭环，但在新 revision 完成发布并证明能从云端恢复前，这项 P0 仍不得关闭。

#### 5. 生产环境密钥与初始化行为需要核实

- **事实**：配置缺省值是 `sqlite:///data/weilan.db`，JWT secret 缺省为 `dev-secret-change-me-in-production`。`backend/app/core/config.py:5-10`、`backend/app/core/config.py:24-30`。
- **事实**：启动时自动执行来源、测试邀请码和运营账号 seed。`backend/app/main.py:66-75`。
- **事实**：空数据库会自动写入五个固定测试邀请码 `WEILAN001`–`WEILAN005`。`backend/app/services/seed.py:38-45`。
- **线上核查事实（2026-08-21）**：`JWT_SECRET`、模型 Key 与运营密码变量均已配置；核查只验证存在性和长度等级，没有读取或记录其值。数据库仍是临时 SQLite。
- **推断**：JWT 与模型配置已不再是当前阻塞，但仍需在生产环境禁用固定测试邀请码 seed；否则空库恢复/重建时会重新出现可猜邀请码。

#### 6. 线上 revision 与 Git 提交缺少可追溯映射

- **事实**：当前稳定 revision 已是后端 6、前端 10，创建于 2026-08-21；revision 描述只有“Triggered by veFaaS CLI v0.3.1”，没有 Git SHA。
- **推断**：在完成上述 P0 修复后，需从同一已标记提交重新部署，并记录 Git SHA、前后端 revision、构建时间和回滚点。

### P1：可邀请试用前应验证

#### 7. 进程内定时器和 daemon 线程不等于可靠云任务

- **事实**：APScheduler 随 FastAPI 进程启动，45 分钟采集与 08:00 日报任务均在进程内运行。`backend/app/main.py:37-63`、`backend/app/main.py:77-92`。
- **事实**：提交/轮询任务由 daemon thread 执行；进程结束时线程不会保证执行完成。`backend/app/services/jobs.py:66-82`。
- **事实**：08:00 任务捕获所有异常后直接 `pass`，不会进入 `Job` 失败记录。`backend/app/main.py:51-63`。
- **线上核查事实（2026-08-21）**：前后端都没有 veFaaS Timer 触发器、定时预留策略或弹性策略；函数触发器只有 APIG。近期实例日志只证明应用启动和 HTTP 请求，没有可核验的日报定时执行记录。
- **推断**：在 serverless 环境中，实例重启、多实例、发布切换或进程回收会导致漏跑、重复跑或静默失败。需要明确采用“保持单实例并加强日志/锁”还是“迁移到云端定时触发 + 可重入任务”。

#### 8. 08:00 当前不会自动公开

- **事实**：`_daily_report_job` 只执行事件提取和日报生成；生成结果为 `draft`，没有调用发布服务。`backend/app/main.py:51-61`、`backend/app/services/report_generation.py:123-134`。
- **事实**：当前人工发布要求所有候选先通过质检。`backend/app/services/admin.py:538-552`。
- **结论**：用户确认的“08:00 自动公开”是新增行为，不能仅改定时表达式。需要定义自动质量门：生成成功且满足最低内容/证据规则才替换公开日报；失败时保留上一份已发布日报并留下可见错误。

#### 9. 真实模型未配置时会生成看似可用的 mock 内容

- **事实**：只有设置模型 Key 时才调用模型，否则日报自动生成带 `[模拟]` 的内容。`backend/app/services/llm.py:18-20`、`backend/app/services/report_generation.py:68-89`、`backend/app/services/report_generation.py:115-120`。
- **事实**：事件提取也在无 Key 时走 mock。`backend/app/services/event_extraction.py:52-69`、`backend/app/services/event_extraction.py:94-104`。
- **推断**：线上必须检查 Key、模型请求、失败告警和内容显式标记，禁止把 mock 或陈旧内容展示成“今日真实日报”。这也符合 PRD 的异常规则。`PRD.md:651-660`。

#### 10. 邮件 UI/记录会显示成功，但实际上不发信

- **事实**：邮件服务直接写 `sent`，正文链接硬编码为本机 `http://127.0.0.1:3000/mine`，随后只写日志，不调用邮件供应商。`backend/app/services/mail.py:13-30`。
- **推断**：若首轮不接邮件，应把用户可见状态改为“未启用/人工通知”，避免错误宣称已送达；若首轮要求邮件，则这项升级为 P0。

#### 11. 浏览器 token 仍为 localStorage 方案

- **事实**：创作者与运营者会话虽已分开，但 token 存在 `localStorage`。`frontend/lib/auth.ts:1-19`、`frontend/lib/auth.ts:35-69`。
- **事实**：阶段文档明确将 JWT + 本地保存 token 标为生产上线前需收紧。`docs/阶段4-技术开发文档.md:176-180`。
- **推断**：邀请制小流量可在确认风险后限期接受；公开推广前应评估 HttpOnly Cookie、XSS 防护、令牌有效期和退出/吊销策略。

### P2：不阻塞“受邀可运行”，但阻塞商业验证

- 真实邮件与退订、自动支付、完整行为漏斗、正式协议/隐私政策、内容更正与来源下架、续订验证。统一证据：`PRD.md:663-693`。
