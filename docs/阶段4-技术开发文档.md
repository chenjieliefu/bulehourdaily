# 第 4 阶段技术开发文档｜邀请注册 + 创作者画像 + 个性化日报

> 配套文档：《微蓝日报 PRD》、《通用技术栈手册》、《技术适配声明》。
> 本文档只覆盖第 4 阶段。

## 一、阶段目标

对齐 PRD「一周 MVP 交付计划」的 **Day 5**，以及 **FR-10、FR-11** 和 FR-15 的注册/体验部分。

- **交付范围**：
  1. 邀请码注册 + 登录（邀请制）。
  2. 创作者画像：6 项字段，可保存、可修改（只影响之后生成）。
  3. 个性化日报：按画像从共享热点池重选 3 个选题、重写角度，保留证据与可信度。
  4. 体验资格：每用户最多 3 份个性化日报（3 天体验），用完即止（订阅在阶段 5）。
  5. 前端：登录/注册页、画像页、个性化日报页。
- **阶段产物**：受邀创作者能「注册 → 填画像 → 看到适合自己账号的 3 个选题」。
- **明确不做**：创作方案展开、发布反馈、邮件、付费订阅（阶段 5）；质检（阶段 6）。
- **主链路**：`注册(邀请码) → 填画像 → 生成个性化日报(LLM) → 网页查看`。

## 二、技术适配摘要

- 采用：FastAPI、Pydantic、SQLAlchemy、pytest、LLM 调用层（已有）。
- 启用：鉴权（JWT + 密码哈希）、个人化数据表。
- 开发路径：后端先行 + 最小验收界面（复用现有 Next.js 前端加页面）。

## 三、技术栈与模型

- 密码哈希：`hashlib.pbkdf2_hmac`（标准库，加盐）。
- 会话令牌：JWT（`PyJWT`，新增依赖）。
- 个性化日报生成：DeepSeek（同一 LLM 客户端），mock 模式不变。

## 四、环境与配置

- 新增 `JWT_SECRET`（`.env`，本地开发给默认值；生产必须换强随机值）。
- 无新增外部服务；无需新 Key。

### 状态与规则（确定性）

- **体验资格**：`count(个性化日报) < 3` 才可生成；达到 3 停止（订阅阶段 5 接入）。
- **个性化不改事实**：个性化选题必须引用共享 `hot_event`，证据与可信度标签复用通用事件。
- **画像修改**：只影响之后生成的日报，历史日报不变。

## 七、API / 工具设计

| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| POST | /api/v1/auth/register | 邀请码 + 邮箱 + 密码注册 | 否 |
| POST | /api/v1/auth/login | 邮箱 + 密码登录，返回 token | 否 |
| GET | /api/v1/profile | 获取我的画像 | 是 |
| PUT | /api/v1/profile | 保存/更新画像 | 是 |
| POST | /api/v1/personalized/generate | 生成今日个性化日报（长任务，提交+轮询） | 是 |
| GET | /api/v1/personalized/reports | 我的个性化日报列表 | 是 |
| GET | /api/v1/personalized/reports/{id} | 详情 | 是 |

- 鉴权：`Authorization: Bearer <JWT>`；注册/登录外所有个人接口必须带 token。
- 错误统一结构不变。

## 八、Prompt 设计（personalization.md）

- 角色：根据创作者画像 + 共享热点事件，生成个性化日报。
- 输入：画像 6 项 + 新鲜热点事件（同通用日报的新鲜过滤）。
- 输出 JSON：`{"summary","reason","topics":[{"event_id","title","what_happened","why_now","angle","hook","structure","visual","time_window","recommendation_reason"}]}`。
- 约束：只改「选哪个、怎么讲」，不得改事件事实；推荐理由必须联系画像（如"你的观众是 XX，这个更适合你"）。

## 九、验收界面

复用现有 Next.js 前端，新增：
1. **登录页 / 注册页**：邮箱+密码，注册需填邀请码。
2. **画像页**：6 项字段表单，保存/修改。
3. **我的日报页**（`/mine`）：展示个人个性化日报（结构与公开日报一致，多一行「为什么推荐给你」）。
4. 侧栏增加「我的日报」，登录态显示用户邮箱。

## 十、测试要求

### 第一层 mock 测试（离线）

1. 密码哈希/校验、JWT 签发与校验。
2. 注册：邀请码一次性使用、重复邮箱拒绝、弱密码拒绝。
3. 登录：错误密码拒绝、正确返回 token。
4. 画像：未登录不可访问、保存/更新生效。
5. 个性化生成（mock LLM）：按画像生成选题、事件引用共享热点、证据/可信度复用。
6. 体验资格：第 4 次生成被拒绝；第 3 次成功。
7. 权限：A 用户看不到 B 用户的画像/个性化日报。

### 第二层真实冒烟（验收前）

- 真实 DeepSeek 跑通：`真实事件 → 按画像生成个性化日报 → 网页可见`，检查「推荐理由」是否真的联系了画像。

## 十一、验收清单（产品经理可照做）

- [ ] 我用一个邀请码注册成功，重复用同一邀请码被拒绝。
- [ ] 我登录后能填 6 项画像并保存，修改后再生成会用新画像。
- [ ] 我点「生成个性化日报」，能看到 3 个选题，每个有「为什么推荐给你」，且和公开日报明显不同。
- [ ] 选题里的事件时间/证据/可信度标签和公开日报一致（没改事实）。
- [ ] 我生成 3 份后，第 4 次提示体验次数已用完。
- [ ] 换一个账号登录，看不到第一个账号的画像和日报。

## 十二、风险与待确认项

- **鉴权简化**：MVP 用 JWT + 前端本地保存 token（未用 HttpOnly Cookie），生产上线前收紧（见上线手册）。
- **体验次数**：按「成功生成的个性化日报份数」计数（PRD FR-15），阶段 5 接入订阅后统一。
- 需要产品经理决定的问题：无。
