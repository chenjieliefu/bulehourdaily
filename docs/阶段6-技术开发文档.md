# 第 6 阶段技术开发文档｜轻量质检 + 真实数据演练 + 首批邀请

> 配套文档：《微蓝日报 PRD》、《通用技术栈手册》、《技术适配声明》。
> 本文档只覆盖第 6 阶段（PRD Day 7）。

## 一、阶段目标

对齐 PRD「一周 MVP 交付计划」的 **Day 7**，以及 **FR-08（发布前轻量质检）** 和上线检查清单（§16）。

- **交付范围**：
  1. 轻量质检页：运营者查看今日 3 个主选题 + 证据 + 候选事件，可**通过/拒绝/编辑文案/补充选题**。
  2. 发布日报：质检通过后把通用日报从 `draft` → `published`；未质检不得发布。
  3. 邀请码批量生成：为 5-9 位首批创作者发邀请码。
  4. 真实数据演练：连续用真实数据生成日报的操作流程（见验收清单）。
- **阶段产物**：运营者每天 10-15 分钟能完成质检并发布日报；首批邀请码可发。
- **明确不做**：自动支付、正式运营后台、纠错与撤回流程（公开推广前做）、实时监控。

## 二、技术适配摘要

- 采用：现有 FastAPI、SQLAlchemy、LLM 层、Next.js 前端。
- 启用：质检 API + 质检页；邀请码批量接口。
- 开发路径：后端先行 + 质检页（运营者用）。

## 三、技术栈与模型

- 补充选题（从候选事件生成新选题）复用 LLM（mock 模式不变）。
- 无新增外部依赖。

## 六、数据、资产与状态

### 变更

- **topic_recommendation** 增加 `reviewed: bool`（默认 false，表示该选题已通过质检）。
- **daily_report.status** 沿用 `draft / published`；发布时写 `published_at`。

### 状态与规则（确定性）

- 发布条件：当日日报存在，且所有剩余选题 `reviewed=True`；否则拒绝发布并提示「还有 N 个选题未质检」。
- 拒绝：删除该选题（软删：保留记录但标记，MVP 先直接删除）。
- 补充选题：从候选热点事件（新鲜、未进入日报）中选一个，LLM 生成通用选题，`reviewed=True`（运营者已选定即视为通过）。
- 历史日报：发布后规则变更不回头改历史（PRD 12.2）。

## 七、API / 工具设计

| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| GET | /api/v1/admin/review | 今日日报 + 3 选题 + 候选事件 + 证据 | 运营者 |
| PUT | /api/v1/admin/topics/{id} | 编辑选题文案（title/what_happened/why_now/angle/hook/structure/visual/time_window） | 运营者 |
| POST | /api/v1/admin/topics/{id}/approve | 通过该选题 | 运营者 |
| DELETE | /api/v1/admin/topics/{id} | 拒绝（删除）该选题 | 运营者 |
| POST | /api/v1/admin/topics | 从候选事件生成一个新选题（body: event_id） | 运营者 |
| POST | /api/v1/admin/report/publish | 发布当日日报 | 运营者 |
| POST | /api/v1/admin/invite-codes | 批量生成邀请码（body: count） | 运营者 |
| GET | /api/v1/admin/invite-codes | 邀请码列表 | 运营者 |

- 运营者鉴权：MVP 本地直调（无独立登录），**公开上线前必须加运营者鉴权**（记入风险）。

## 八、Prompt 设计

- 补充选题复用现有「日报生成」Prompt 的单选题变体：给定一个事件 + 通用创作者视角，生成一个完整通用选题。
- 输出 JSON：`{"title","what_happened","why_now","angle","hook","structure","visual","time_window"}`。

## 九、验收界面

质检页 `/review`：
1. 顶部：今日日报状态（草稿/已发布）+ 「发布日报」按钮。
2. 三个主选题卡：每个有「通过 / 拒绝 / 编辑」。
3. 候选事件列表：每条有「补充为选题」。
4. 邀请码区：批量生成 + 列表。

## 十、测试要求

### 第一层 mock 测试（离线）

1. 质检：通过选题 → reviewed=true；拒绝 → 删除。
2. 编辑文案字段生效。
3. 补充选题：从候选事件生成并 reviewed=true；引用事件证据。
4. 发布：存在未质检选题时拒绝发布；全部通过后可发布（status=published, published_at 写入）。
5. 邀请码：批量生成 N 个，唯一，未使用。
6. 历史不变：发布后修改规则不回写历史日报。

### 第二层真实冒烟（验收前）

- 真实 DeepSeek 跑通：`候选事件 → 补充生成选题 → 质检通过 → 发布日报`。

## 十一、验收清单（产品经理可照做）

- [ ] 打开质检页，能看到今日 3 个选题和候选事件，证据链接可点。
- [ ] 对某个选题点「拒绝」，它从日报里消失。
- [ ] 编辑某个选题的标题/钩子，保存后生效。
- [ ] 从候选事件点「补充为选题」，等一会儿生成一个新选题并进入日报。
- [ ] 在有未质检选题时点「发布」，被拒绝并提示。
- [ ] 全部通过后点「发布」，日报状态变「已发布」。
- [ ] 批量生成 5-9 个邀请码，能看到列表。
